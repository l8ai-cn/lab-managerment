## Users

| 角色 | 场景 | 核心任务 |
|------|------|----------|
| 系统管理员 | 办公室桌面端 | 用户/权限/系统对接/全局配置 |
| 院系管理员 | 办公室桌面端 | 本院实验室 oversight、审批监督 |
| 实验室管理员 | 实验室或办公室 | 设备台账、预约审批、变更审核、故障处理 |
| 教师 | 办公室/机房 | 实验项目维护、科研实验、预约仪器/实验室 |
| 学生 | 机房/移动端 | 查看实验室、预约、故障上报 |
| 临时人员 | 移动端 | 有限预约与故障上报 |

**使用情境：** 高校 B/S 管理系统，工作日高频操作（预约、审批、台账），学期初批量导入，期末数据填报。用户期望「专业可信、信息清晰、操作高效」，而非营销页或消费级 App 的活泼感。

## Product Purpose

LabOS 是面向高校的实验室综合管理平台，覆盖 12 大业务模块、87 项交付功能。设计服务于**数据密集型后台操作**：表格筛选、表单录入、多级审批、日历预约、统计大屏。

**成功标准：** 管理员 3 秒内找到目标模块；表格一屏展示足够信息密度；审批/预约状态一眼可辨；学生端简洁不越权。

## Brand Personality

**三个词：** 精确 · 可信 · 高效

- **精确** — 像实验室仪器读数：对齐、等宽数字、状态色有语义
- **可信** — 校方采购级专业感，克制用色，无渐变装饰
- **高效** — Linear 级信息密度，减少无意义留白和点击层级

## Anti-references

| 反例 | 原因 |
|------|------|
| Ant Design 默认深色侧边栏 + 蓝色主按钮 | 用户明确拒绝，「10 年前设计」 |
| 巨大 Empty 状态图标撑满屏幕 | 已发生 Tailwind 未编译 bug，绝不再现 |
| `max-width: 1600px` 内容区 + 右侧大片留白 | 用户明确愤怒 |
| 渐变 Hero 卡片 + 6 列 KPI 折行 | 旧版 AI 味设计 |
| 消费级圆角卡片堆叠 | 不适合 12 模块 CRUD 后台 |

## Design Principles

1. **导航即产品** — 侧边栏是 12 模块的地图，不是装饰脚手架
2. **状态色即语义** — 颜色传达设备/预约/审批状态，不做装饰
3. **一屏一焦点** — 每个视图有一个明确 focal element（表格、日历、KPI）
4. **密度分层** — 表格区紧凑（12–16px），区块间留白（48px）
5. **侧边栏与画布同色** — 用边框分隔，不用「两个世界」的深浅对比

## Accessibility & Inclusion

- WCAG 2.1 AA 为目标
- 键盘导航、focus-visible 环、44px 最小点击区域
- `prefers-reduced-motion` 尊重
- 中文界面为主，Noto Sans SC 保证 CJK 可读性
